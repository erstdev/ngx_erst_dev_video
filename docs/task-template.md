# Карточка задачи для нового чата

Скопируй шаблон, заполни и вставь в новый чат. Не копируй весь `CONTEXT.md` и
не перечисляй все компоненты.

```md
# Спринт N / <Кирпич>

## Цель

<Одно-два предложения.>

## Прочитать только это

- `CONTEXT.md` — разделы «Сейчас» и «Решения».
- `<путь к целевому компоненту>.ts|html|scss`
- `<путь к демо-заготовке>.ts|html`
- `<один соседний кирпич> — эталон`
- `<общий компонент, если нужен>` (например, DemoShell/CodeSnippet)

## Не читать

- Остальные кирпичи и README пакетов.
- `docs/` целиком; только файл по ссылке, если он реально нужен.
- `dist`, `node_modules`, историю чата.

## API

- Входы: ...
- Выходы: ...
- CSS-переменные: ...
- `customClass` / `ng-template`: ...

## Ограничения

- Angular 22, standalone, signals, `input()`/`output()`, OnPush.
- Без новых зависимостей и тестов.
- Публичный API `core` не менять.
- Документация и комментарии — на русском.

## Готово, когда

- [ ] Компонент реализован.
- [ ] README кирпича рядом с компонентом.
- [ ] Демо-страница `ready` с блоками «Код примера».
- [ ] `prettier`, `nx lint`, `nx build` зелёные.
- [ ] Браузерная проверка (если UI).
- [ ] `CONTEXT.md` и `docs/` обновлены.
```

## Почему так

- Явный список файлов не даёт агенту «осмотреться» и прочитать полрепозитория.
- Один кирпич на чат не упирается в контекст.
- API и критерии готовности сразу задают рамки, и агент не изучает соседние
  реализации, чтобы угадать контракт.
