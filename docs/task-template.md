# Карточки задач для нового чата

Скопируй подходящую карточку, заполни и вставь в новый чат. Не копируй весь
`CONTEXT.md`, не пересказывай план и не перечисляй компоненты.

Пункт плана берётся из `docs/roadmap.md` — один пункт из одного шага.

## Карточка кирпича

```md
# Шаг <N> / <Кирпич>

## Цель

<Одно-два предложения.>

## Прочитать только это

- `CONTEXT.md` — разделы «Сейчас» и «Решения».
- `<путь к целевому компоненту>.ts|html|scss`
- `<путь к демо-заготовке>.ts|html`
- `<один соседний кирпич> — эталон`
- `<общий компонент, если нужен>` (например, DemoShell/CodeSnippet)

## Не читать

- Остальные кирпичи и README пакетов.
- `docs/` целиком; только файл по ссылке, если он реально нужен.
- `dist`, `node_modules`, историю чата.

## API

- Входы: ...
- Выходы: ...
- CSS-переменные: ...
- `customClass` / `ng-template`: ...

## Ограничения

- Angular 22, standalone, signals, `input()`/`output()`, OnPush.
- Без новых зависимостей и тестов.
- Публичный API `core` не менять.
- Документация и комментарии — на русском.

## Готово, когда

- [ ] Компонент реализован.
- [ ] README кирпича рядом с компонентом.
- [ ] Демо-страница `ready` с блоками «Код примера».
- [ ] `npx nx format:check --all`, `npx nx affected -t lint,build` зелёные.
- [ ] Браузерная проверка (если UI).
- [ ] `CONTEXT.md` и `docs/` обновлены.
```

## Карточка инфраструктурной задачи

Для сайта, публикации, CI, решений — всего, что не кирпич.

```md
# Шаг <N> / <задача>

## Цель

<Одно-два предложения: что должно появиться.>

## Зависит от

<Пункт плана, который уже должен быть закрыт. Если ничего — «ни от чего не зависит».>

## Прочитать только это

- `CONTEXT.md` — раздел «Сейчас».
- `docs/roadmap.md` — только «Шаг <N>».
- `<2–3 целевых файла: конфиг, README пакета, YAML и т. п.>`

## Не читать

- Другие шаги плана, `docs/journal.md`, историю чата, `node_modules`, `dist`.

## Решение (если задача — выбор)

- Варианты: ...
- Критерии выбора: ...

## Готово, когда

- [ ] <результат>
- [ ] `npx nx format:check --all` зелёный; для кода — ещё `npx nx affected -t lint,build`.
- [ ] Пункт отмечен в `docs/roadmap.md`, строка добавлена в `docs/journal.md`.
```

## Почему так

- Явный список файлов не даёт агенту «осмотреться» и прочитать полрепозитория.
- Один пункт плана на чат не упирается в контекст.
- API и критерии готовности сразу задают рамки: агенту не надо изучать соседние
  реализации, чтобы угадать контракт.
- Поле «Зависит от» ловит попытку начать заблокированную работу: план отсортирован
  по зависимостям, и это самый частый способ потратить чат впустую.
