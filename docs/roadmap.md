## CI: как устроено (справочно)

Одна джоба — одна команда: у каждой проверки свой статус. Команды берутся из npm-скриптов
`package.json`, поэтому в GitHub Actions и GitLab CI одинаковые строки.

```
audit  ──┐
         ├──→ lint
format ──┘    → build
```

- `audit` (`ci:audit`) и `format` (`ci:format`) — по ~2 c. Идут первыми и падают первыми:
  не тратим минуты сборки на уязвимость или опечатку.
- `lint` (`ci:lint`) и `build` (`ci:build`) — по ~30 c. Ждут дешёвые джобы и идут параллельно.
- `build` отдаёт артефакт `dist/` (шаг внутри джобы, не отдельная джоба).
- Каждая джоба сама ставит зависимости: отдельный runner, `node_modules` не переиспользуется.

**Измеренная цена гейта** (коммит `197cca6`): одна джоба `verify` — 76 с в GitHub;
четыре джобы с гейтом — 125 с в GitHub и 147 с в GitLab. Разница почти вся — второй круг
`npm ci`. Если скорость важнее fail-fast: убрать `needs` в GitHub и свести стадии GitLab
к одной.

Format проверяет **весь** репозиторий: флаг `--all` обязателен. Без него `nx format:check`
берёт `git diff` против `defaultBase` и на push в `master` не проверяет ничего (а в GitLab
падает на отсутствующей ветке при shallow-клоне).

Audit без порогов: `--audit-level=low` падает на любой severity. Плата: новая
moderate-запись в базе advisories покрасит сборку без изменений в коде.

Не добавляем в пайплайн: `tsc --noEmit` (типы уже проверяет сборка), `npm audit fix`
(меняет lockfile), `npx npm@10 ci --dry-run` (в CI избыточно: `npm ci` и так идёт под npm 10;
полезно локально перед пушем, где npm 11).
